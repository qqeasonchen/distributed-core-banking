# 架构方案

## 总体分层

```
渠道层（手机银行 / 网银 / 柜面 / 开放 API）
        ↓
集成层（企业服务总线 / API 网关 / 服务网格）
        ↓
核心层（微服务：账户、存款、贷款、支付、清算、总账）
        ↓
数据层（分布式数据库 + 缓存 + 消息队列）
        ↓
基础设施（x86 集群 / 容器平台 K8s / 多数据中心）
```

## 微服务拆分

单体核心通常按业务域拆分为：

- 客户信息管理（CIF）
- 存款服务（活期 / 定期）
- 贷款服务（放款 / 还款 / 计息）
- 支付与清算服务
- 总账服务
- 公共服务（日终批量、参数管理、额度）

常用技术栈：Spring Cloud / Dubbo、Kubernetes、服务注册发现（Nacos / ZooKeeper）、分布式事务框架（Seata 等）。

## 事务一致性

核心账务要求强一致，分布式架构下常用方案：

| 方案 | 说明 | 适用 |
|---|---|---|
| Raft / Paxos 多数派 | 分布式数据库内部副本一致性 | 数据库层 |
| TCC（Try-Confirm-Cancel） | 业务层两阶段补偿 | 跨服务转账 |
| Saga | 长事务拆分为本地事务序列 + 补偿 | 跨域流程 |
| 最终一致 + 对账 | 异步消息 + 日终核对 | 非关键路径 |

## 分布式数据库

见 [databases.md](../databases.md)。共性能力：

- 计算存储分离，水平扩展
- Multi-Raft / Paxos 多副本强一致
- 分布式事务（全局时钟 / TSO 或 Hybrid Logical Clock）
- 兼容 MySQL / Oracle 语法，降低迁移成本

## 高可用与多活

| 方案 | RPO / RTO | 说明 |
|---|---|---|
| 同城双活 | RPO≈0 | 两机房同时承载流量，延迟敏感 |
| 两地三中心 | RPO≈0 / 分钟级 | 同城双活 + 异地灾备 |
| 异地多活 | RPO≈0（单元化） | 按用户分片（单元化 / Set 化），多地同时提供服务 |

单元化（Set 化）是蚂蚁 LDC（Logic Data Center）架构的核心思想：将数据和流量按维度切分到独立单元，单元内闭环，故障时整体切换。

## 日终批处理改造

集中式核心依赖大型机批处理窗口；分布式化后需要：

- 批处理任务调度拆分与并行化（如按账户分片）
- 批量与联动的资源隔离
- 核对平台：账证核对、总分核对自动化
