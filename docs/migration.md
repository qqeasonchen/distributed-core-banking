# 迁移方法论

核心系统改造最难的不是新技术，而是**迁移切换**——核心系统一天都不能停。

## 改造路径选择

| 路径 | 说明 | 适用 |
|---|---|---|
| 直接重构 | 全新架构重写核心 | 中小银行、新建银行 |
| 渐进式下移 | 按业务模块逐步迁移 | 大型银行 |
| 双核并行 | 新老核心同时运行一段时间 | 过渡期风控要求高的银行 |
| 外围先行 | 先改造渠道、外围系统，核心最后动 | 风险最敏感的银行 |

## 双轨并行 + 灰度切流（标准打法）

1. **双轨运行**：新老核心同时记账，交易双发或镜像回放
2. **数据核对**：逐笔比对两套系统的账务结果（余额、流水、总账）
3. **灰度切流**：按客户 / 业务 / 网点维度逐步把流量切到新核心
   - 内部员工 → 少量白名单客户 → 某区域 / 某业务线 → 全量
4. **回退预案**：每个灰度阶段必须有可快速回退的开关
5. **全量切换**：核对通过后全量切换，老核心转为只读，观察期后下线

## 关键工程问题

- **数据迁移**：历史数据（几十年账务）搬迁与格式转换；新旧科目映射
- **停机窗口**：能否做到秒级 / 分钟级切换（依赖数据同步链路 RPO≈0）
- **性能对齐**：新核心吞吐需满足峰值（可用全链路压测验证）
- **批处理对齐**：日终批量结果与老核心逐科目核对
- **外围系统适配**：数百个外围系统的接口改造与回归测试

## 风险清单

- 老核心逻辑"黑盒"：缺乏文档，隐性规则在迁移中丢失 → 需要交易回放比对
- 切流后长尾问题：低频业务（销户、挂失、司法冻结）未覆盖测试
- 双轨期间成本翻倍，核对平台本身成为新系统
